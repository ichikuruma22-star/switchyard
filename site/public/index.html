The native engine uses Switchyard Gateway for model access: OpenAI, Anthropic, Gemini, or a local Ollama server with no API key. The Codex, Claude Code and Antigravity integrations connect to your own installations.

Named profiles keep each agent’s accounts separate. Codex, Claude Code and Antigravity conversations run inside the workspace; managed Claude Code and Antigravity profiles can also open in their own terminal.

From download
to first task.

Four steps on Windows 10 or 11. The user guide covers each one in detail.

  1. Download and extract

    Extract the whole Windows ZIP to a folder. Install the Visual C++ x64 runtime and the WebView2 Runtime if they’re missing.

  2. Open your project

    Start switchya-desktop.exe, choose Open a project and enter an existing folder. Switchya works on the files where they are.

  3. Connect a model

    Choose Connect a provider: OpenAI, Anthropic or Gemini with your API key, or a local Ollama server with no key. Codex, Claude Code and Antigravity keep their own sign-in.

  4. Send a task, then review

    Describe the task and choose Send task. With the native engine, file edits appear as diffs and commands wait for your decision.

Known limits

  • Portable ZIP for Windows 10/11 x64. It is unsigned, with no installer or bundled runtimes.
  • No macOS or Linux desktop download yet. Source is available on GitHub for other platforms.

  • Claude subscription quota isn’t shown, and Switchya can’t check Antigravity sign-in status.

Questions.

Short answers about cost, data, models, updates and getting help. The user guide and security model have the details.

Is Switchya free?

Yes. Switchya and Switchyard Gateway are open source under the MIT License. Cloud model providers bill their usage to your own account or subscription.

Does my code leave my computer?

Switchya has no analytics or telemetry, no Switchya account and no cloud sync, and its local server only accepts connections from your own computer. A task sends the conversation and the files the agent reads to the model provider you chose for it. With a local Ollama model it stays on your machine. Codex, Claude Code and Antigravity handle data under their own terms.

Which models can I use?

The setup dialog connects OpenAI, Anthropic, Gemini or a local Ollama server, and the model list shows the IDs your connection offers. Switchyard Gateway’s configuration adds compatible endpoints, aliases and failover. You can also work through your own Codex, Claude Code or Antigravity setup.

Will it change my files without asking?

Not with the native engine: file edits are shown as diffs and commands wait for your approval before they run. Codex and Claude Code approval requests appear in the conversation for your decision, and Antigravity runs in read-only plan mode.

Where are my projects and conversations stored?

Your code stays in your project folder, and Switchya edits it in place. Settings and saved conversations are in %LOCALAPPDATA%\Switchya on your PC, not in the ZIP. Keep gateway.toml there private: it holds the API keys you saved.

Why does Windows warn when I open it?

The preview isn’t code-signed yet, so Microsoft Defender SmartScreen may warn about an unrecognized app. Compare the ZIP’s SHA-256 with the value listed under Downloads before you run it:

Get-FileHash .\switchya-0.1.0-preview.4-windows-x86_64-portable.zip
How do I update to a new preview?

Switchya doesn’t update itself. New previews are published on the GitHub releases page. Close the desktop app and any switchya serve terminal, extract the new ZIP into a new folder and start it from there. Your settings, accounts and conversations stay in %LOCALAPPDATA%\Switchya.

Is there a Mac or Linux version?

Not as a desktop download yet. The browser workspace and CLI build from source, and their tests pass on Linux and macOS, but the desktop shell isn’t released there. Switchyard Gateway has release builds for Windows, Linux and macOS.

How do Switchya and Switchyard Gateway relate?

Switchya is the app and CLI. Switchyard Gateway is a standalone API gateway that the native engine uses for model access. You can also run the Gateway on its own for other tools and SDKs.

Where can I get help or report a bug?

The user guide covers setup, approvals, accounts and recovery. To report a bug or ask a question, open an issue on GitHub. Issues are public, so leave out API keys and private code.
