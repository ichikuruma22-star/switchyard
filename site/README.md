The live site links to the Windows x64 portable preview `0.1.0-preview.4`, containing the native desktop shell and CLI, and to the separate public Gateway release `v0.1.1`.

## Preview and checks

Node.js 22 or newer:

```sh
node preview.mjs
# http://127.0.0.1:18742

npm run check
```

`npm run check` also confirms that the FAQ structured data in `index.html` repeats the visible questions and that its download URL is the page's download link. After changing anything in `public/`, run `npm run manifest` to regenerate `asset-manifest.json`. After a deployment, `npm run readback -- VERSION_ID "what changed" > deployment-readback-DATE-LABEL.json` reads every published file back from switchya.com, checks www, the HTTPS redirects, the custom 404 and the security headers, and exits non-zero on any mismatch.

The preview server binds only to loopback and applies the site's global response headers. It does not emulate every Cloudflare routing or caching behavior. Set `SWITCHYA_SITE_PORT` to change its port. No package installation is required for this preview or the checks.

For Cloudflare's local static-asset behavior, install the pinned development dependency and use `npm run dev:cloudflare`. Stop the lightweight server first because both use port 18742.

## Hosting configuration

`wrangler.jsonc` uses Workers Static Assets with `public/` as the asset directory and `404-page` handling. Custom-domain routes attach switchya.com and www.switchya.com; workers_dev is disabled. No Worker code, account ID in source, storage binding, or backend is configured. `public/_headers` supplies the security policy. Static files and fonts are served from the same origin.

Wrangler is pinned to **4.149.0**, verified against the npm registry on 11 October 2026. Its Miniflare dependency uses patched `sharp 0.35.5`, addressing [GHSA-wq5f-xc86-pv6w](https://github.com/advisories/GHSA-wq5f-xc86-pv6w) in the development tooling. Its declared Node requirement is `>=22.0.0`. The compatibility date is `2026-10-03`.

For an authorized update after visual review, verify the account with `npx wrangler whoami`, run the checks and a deployment dry run, then use `npm run deploy`. Read back both domains, assets, custom 404, HTTPS redirects, and headers afterward. Regenerate asset-manifest.json when public files change. The global cache policy includes no-transform; at the last deployment read-back, live HTML matched its deployed source byte for byte, with no injected analytics beacon. The font rule replaces the global Cache-Control value with a 30-day cache policy.

`no-transform` also stops Cloudflare from compressing a response ([Cache-Control: gzip and other compression](https://developers.cloudflare.com/cache/concepts/cache-control/#gzip-and-other-compression)). On 28 October 2026 the live `index.html` and `site.css` were served uncompressed (28,848 and 34,282 bytes) to a client that accepted Brotli and gzip. HTML keeps `no-transform`, which keeps the pages byte for byte and stops Cloudflare from injecting [JavaScript Detections](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/javascript-detections/#if-your-origin-sends-a-no-transform-header) or the [Web Analytics beacon](https://developers.cloudflare.com/web-analytics/faq/) into them. Bot Fight Mode turns JavaScript Detections on, and its script loads from the site's own `/cdn-cgi/challenge-platform/` path, which the `script-src 'self'` policy would allow. The `/site.css` and `/site.js` rules replace the global value with `public, max-age=0, must-revalidate`, so Cloudflare can compress them (locally, Brotli reduces the stylesheet from 34,629 to 6,914 bytes). Node's `fetch` decodes Brotli and gzip, so `npm run readback` still compares the original bytes with the manifest. After the next deployment, `curl -sI -H "Accept-Encoding: br" https://switchya.com/site.css` should report `content-encoding: br`, while the home page stays uncompressed.

## Content and assets

Brand rules live in `../docs/BRAND.md`. The SVG mark is copied unchanged from `../app-ui/assets/switchya-mark.svg`. `favicon.ico` holds that mark rendered at 16, 32 and 48 pixels (PNG entries, rasterised from the SVG with sharp and downsampled) for browsers and tools that request `/favicon.ico` or do not use SVG icons; browsers with SVG icon support still use the SVG. Archivo and JetBrains Mono are copied from the app's self-hosted font files, with their OFL notices.

The page sections are the hero, the workspace, model access, "From download to first task" (four steps taken from the user guide), Switchyard Gateway, downloads and known limits, and a Questions section of ten `<details>` answers that work without JavaScript. Each answer states only what the docs and code support: no analytics or telemetry (no such code in the app or desktop shell), no Switchya account or cloud sync and a loopback-only local host (the user guide's "Current boundaries"), data stored under `%LOCALAPPDATA%\Switchya`, local Ollama models through the provider setup dialog, the MIT License, the unsigned-ZIP SmartScreen warning with a `Get-FileHash` check, updating by extracting the new ZIP into a new folder (the `preview.4` release notes; there is no automatic update service), and help through the user guide and public GitHub Issues. The repository has no SECURITY.md and private vulnerability reporting is off, so the site names no security contact. The answers describe the published preview. When a release ships opt-in automatic approval for trusted projects (PR #7, newer than `preview.4`), update "Will it change my files without asking?" and its structured-data copy to say approval is the default and can be turned off per project. The workspace list includes the project workbench (Files, Changes, Terminal and Handoffs) and the MCP project context, which ship since `preview.3`. The Gateway copy mentions the public container image, `ghcr.io/ichikuruma22-star/switchyard:0.1.1` for linux/amd64 and linux/arm64, checked anonymously on 28 October 2026. The head carries WebSite, SoftwareApplication (with its processor and runtime requirements), SoftwareSourceCode and FAQPage structured data; the repository link sits on SoftwareSourceCode because `codeRepository` is not a SoftwareApplication property. JSON-LD is a data block, so the `script-src 'self'` policy does not block it. The site follows the visitor's light or dark system theme; the product illustration stays light in both.

The hero contains labeled, illustrative interface concepts, not screenshots or recorded successful tasks. Its tabs switch explanatory views. All three views remain readable without JavaScript. The workspace view uses the built-in agent's wording from `preview.4`: **New session**, **Sessions**, **Choose model**, **Writes and commands need approval**, **Send task**, **Actions & results** and **Local app connected**. The only clipboard action copies the existing `switchyard` Gateway startup command. The PowerShell CLI examples match the current native CLI parser and assume the CLI is on PATH, an existing project folder and a configured model.

The live Switchya download targets the Windows portable ZIP at tag `switchya-v0.1.0-preview.4`; other platforms are source-only and there is no macOS binary. Named Codex, Claude Code and Antigravity accounts are described without promising verified live authentication or usage. Claude Code runs in the workspace (an external terminal remains optional for managed profiles) and has no quota display; Antigravity sign-in status cannot be checked. There is no mailing-list signup, pricing page, unsupported competitor claim, or fabricated adoption data. Before future publication, check the release and asset anonymously. The original design passed desktop, tablet, phone and narrow-screen layout checks and mouse/ArrowRight/Home/End preview-tab navigation. On 28 October 2026 an axe-core 4.10.3 audit (WCAG 2.2 AA plus best-practice rules) found no violations in the light and dark themes at 1440 and 390 CSS pixels, on every preview tab and with every FAQ answer open. All 42 keyboard stops showed a visible focus ring in order, and at the equivalent of 200% zoom (640 CSS pixels) the page reflowed with no horizontal scrolling or clipped text; the main navigation stays on one row from 360 pixels and wraps at 320. Screen-reader testing remains unverified.

Windows contrast themes (`forced-colors: active`) drop box shadows and author background colours, which hid the selected preview tab's underline and the diagram connectors. In that mode the selected tab now gets a `Highlight` border and an underline, and connectors, status dots and list markers use `CanvasText`. This rule, the two added answers, the workbench item and the extra footer link postdate the 28 October audit and still need a browser check.
